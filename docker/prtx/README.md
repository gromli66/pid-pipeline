# prtx — сборка расчётной схемы САПФИР на сервере

Контейнер с движком САПФИР: принимает граф и ключ лицензии, отдаёт `.prtx`.
Клиенту коробка конвертера больше не нужна — он отдаёт только ключ.

## Почему так

Движок Windows-нативный, но в Linux поднимается и считает то же самое:
дамп полученного `.prtx` совпадает с windows-прогоном **байт-в-байт** —
проверено трижды (эталонный граф через CLI и через сервис, реальная схема
243 КБ + скан 2.4 МБ через эндпоинт API).

Держало конвертацию на клиенте не железо, а **файл ключа** `~/.S$lk$.bin`:
`LicenseChecker` читает его сам, офлайн, внутри JVM — переадресовать проверку
некуда. Поэтому ключ приезжает с запросом, живёт в tmpfs (`/dev/shm`) на время
одного прогона и удаляется. На диск сервера не попадает, в БД и логи не
пишется, между запросами не существует.

Юридическая граница этим не снимается: лицензия выдана на рабочее место.
Схема лишь не создаёт общего ключа на всех — каждый оператор работает своим.

## Сборка образа

Контекст сборки — **коробка конвертера** (`C:\project\prt_convertor\converter-box`,
свой git, ~250 МБ); в этом репозитории её нет. Скрипт готовит временный контекст:

```bash
powershell -File docker\prtx\build.ps1
```

Ключи: `-Box <путь к коробке>`, `-Tag <имя образа>`. Из контекста выкидываются
windows-dll, исходники java-CLI и накопленные логи движка; jre берётся из
базового `eclipse-temurin:17-jre`. Готовый образ — 1.46 ГБ.

Перед сборкой скрипт делает две вещи, без которых образ уезжал вслепую:

* **канарейка Ду** — падает, если в контексте нет фазы диаметров (`diameter_value`
  в `py/json2xml.py` и `channelDiameters` в `cli-classes/…/ChannelMerger.class`).
  Собранный без неё образ не даёт ошибки: канал без Ду остаётся с заводскими
  0.3 м, а это в САПФИР честный **Ду300**. Пропуск здесь стоит дороже отказа;
* **штамп версии коробки** — `box.commit` с хешем, признаком грязного дерева и
  датой. Уезжает в образ и отдаётся сервисом.

## Версия конвертера внутри образа

Образ приезжает готовым файлом: в `docker-compose.yml` у сервиса `prtx` нет
секции `build`, только `image:`. Значит по работающему контейнеру нельзя понять,
какой конвертер внутри, — для этого и штамп:

```bash
curl -s http://prtx:8081/health
# {"ok": true, "busy": false, "box": {"commit": "82d012c", "dirty": "0",
#                                     "diam": "1", "built": "2026-08-26 11:12"}}
```

`dirty=1` означает, что образ собран из незакоммиченного дерева коробки — такой
на сервер не выкатывать. Пустой `box` — образ собран до появления штампа.

**Ожидаемая версия коробки — не ниже `82d012c`** (диаметры труб `6ac41ab`,
классы `output`/`perehod`/`regulator_electro` `68fb8f6`, перекомпиляция
`9badf10`). Замер расхождения: тот же граф через до-диаметровый `f061a4a` и
через `82d012c` даёт 17 459 различающихся строк лога — символов 131 → 128,
труб 187 → 186, тройников 66 → 69, `.prtx` 306 КБ → 141 КБ. Пересборка
приносит НЕ только диаметры, и приёмку надо делать на всём образе.

Выкатка на сервер (реестра нет):

```bash
docker save pid-prtx:latest | ssh <сервер> docker load
```

Дальше сервис поднимается из `docker-compose.yml` (`prtx`, порт наружу не
открыт — ключ ходит только внутри `pid_network`).

## Проверка после пересборки

Обязательна сверка дампа: собрать эталонный граф и сравнить дамп с
windows-прогоном того же графа. Совпадение размеров файла критерием **не
является** — размер `.prtx` плавает от прогона к прогону, дамп нет.

```bash
docker run --rm --entrypoint json2prtx -v <каталог с ключом>:/lic:ro -v <работа>:/work \
    pid-prtx:latest /work/g.json - /work/out.prtx all
```

## API

- `GET /health` → `{"ok": true, "busy": <идёт ли прогон>}`
- `POST /build` → JSON с base64-полями `graph`, `license`, необязательным
  `image` и `text_mode` (`all`|`bound`|`none`); ответ — `{"prtx": <base64>, "size": n}`

Коды: 400 — плохой запрос, 403 — движок не принял ключ, 422 — граф не разобран,
500 — сбой движка, 504 — не уложился в таймаут.

## Что стоит знать при эксплуатации

- **Схемы считаются по одной.** Движок пишет своё состояние в общий
  `engine/SETTINGS` (Logs, EventLog, s3.ini), поэтому прогоны сериализованы
  замком. Реальные времена: 9 с на схему из 40 символов, 19 с на схему со
  сканом 2.4 МБ.
- **Прогон берёт до 3 ГБ** (`-Xmx3072M`) плюс Xvfb. На CPU-сервере, где уже
  сидят ML-воркеры, это заметная конкуренция за память.
- **Непринятый ключ стоит 5 минут.** Движок не падает, а уходит в модальное
  окно лицензии и сдаётся по своему 300-секундному дедлайну (замер
  2026-08-22) — всё это время очередь стоит. Отсутствие ключа клиент ловит у
  себя до отправки, но испорченный ключ отличить заранее нечем.
- **Сайдкары этапа 1 обязательны.** `json2xml.py` кладёт рядом с XML
  `*.unknow.json` и другие файлы; без них движок молча даёт другую схему.
