# ЗАЧЕМ. Требования проекта заданы через `>=` (это осознанно: боевой образ должен
# собираться со свежими патчами). Но у гейта «ни одного нового красного» другой
# интерес: он обязан менять цвет от ПРАВОК, а не от даты прогона. Без пинов состав
# окружения решает апстрим — любой релиз pytest/PySide6/numpy или ротация образа
# windows-latest красит набор, и разбирать придётся чужой релиз, а не свой дифф.
#
# КАК ПРИМЕНЯЕТСЯ. Только в CI и только как ограничение, не как список установки:
#   pip install -c requirements/constraints-ci.txt -r api.txt -r ui.txt -r dev.txt
# Что ставится — по-прежнему решают файлы требований; здесь только версии, включая
# транзитивные (именно они и уезжают молча). Боевой сборки (worker.txt, Dockerfile)
# файл НЕ касается.
#

# ровно так, как собирает CI: api + ui + dev + shapely. На этом окружении база
# набора воспроизводится (MEASUREMENTS §37).
#
# ПЕРЕСЪЁМ — осознанный шаг, как пересъём базовой линии, и отдельным коммитом:
#   python -m venv ci_env && ci_env/Scripts/pip install -r requirements/api.txt #       -r requirements/ui.txt -r requirements/dev.txt
#   ci_env/Scripts/pip freeze > requirements/constraints-ci.txt   # + вернуть эту шапку
# После пересъёма прогнать `tools/suite_baseline.py --check` в новом venv: если
# красные разошлись — это находка апстрима, её разбирают, а не заминают.
