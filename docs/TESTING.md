## 1. Обзор

Тесты используют **pytest** и расположены в `tests/`. Основные категории: smoke-тесты импортов (worker), unit-тесты рефакторинга (модели, storage, dispatch), интеграционные тесты OCR pipeline (domain profiles, binding, classify), тесты UI-логики (graph flow, validation window) без запуска Qt Application.

Набор **исполняется без Docker, GPU и реальной БД** — SQLite in-memory и MagicMock; замерено на
чистом venv `api+ui+dev+shapely` (MEASUREMENTS §25.2). Два уточнения, без которых фраза читается
неверно:

- «работают» ≠ «зелёные»: часть набора красная своими причинами (на 2026-08-17 — 57 из 746),
  и гейт поэтому «ни одного нового красного», а не «ноль красных» — см. §7.1;
- одно исключение из «без Docker/GPU» — `test_ocr_phase0.py`: он исключён из сбора
  (`tests/conftest.py:17` `collect_ignore`) и запускается только в контейнере с GPU (см. §2).

## 2. Запуск тестов

```bash
# Все тесты
pytest tests/ -v

# Конкретный файл
pytest tests/test_refactoring.py -v

# Конкретный тест
pytest tests/test_refactoring.py::TestUpsertArtifact -v

# С выводом print/stdout
pytest tests/ -v -s

# Остановиться на первом сбое
pytest tests/ -v -x

# Только smoke-тесты импортов
pytest tests/test_worker/ -v
```

Для тестов OCR phase0 (Surya + PaddleOCR) — запуск внутри контейнера `worker_ocr`:

```bash
docker run --rm --gpus all \
  -v ./tests:/app/tests \
  -v ./models/ocr:/models/ocr \
  -e HF_HOME=/models/ocr/hf_cache \
  pid_worker_ocr python /app/tests/test_ocr_phase0.py
```

## 3. conftest.py и fixtures

Файл: `tests/conftest.py`. Выполняет критическую подготовку **до любого импорта app-модулей**:

**Env-переменные.** Устанавливает тестовые значения `DATABASE_URL=sqlite:///test.db`, `STORAGE_PATH`, `PROJECTS_CONFIG_DIR`, `CELERY_BROKER_URL` до импорта `app.config`.

**Patching async engine.** Подменяет `sqlalchemy.ext.asyncio.create_async_engine` и `async_sessionmaker` на `MagicMock` — это предотвращает крэш при импорте `app.db.session` (SQLite не поддерживает asyncpg).

**Sync engine.** Создаёт `SQLite:///:memory:` engine и `sessionmaker`, патчит `app.db.session.engine` и `SessionLocal` — тесты используют синхронный SQLite вместо PostgreSQL.

Порядок инициализации критичен: env vars → patch async → import app → patch sync engine.

**Корпус графов в git** (пункт 0.8, 2026-08-18). `tests/fixtures/graph/` — три самых мелких
`graph_validated.json` (`d74eb9f1`, `089feca2`, `6e7144d5`, ~200 КБ), байт-в-байт копии из
`storage/diagrams/` машины разработки; происхождение и sha256 — `README.md` рядом с ними.
Читать корпус только загрузчиком `tools/corpus.py` (КД7), а не глобом по `storage/`:

```python
from tools import corpus
corpus.corpus_paths()                       # {uid8: путь}: фикстуры + локальный storage
corpus.corpus_paths(include_storage=False)  # только то, что есть в git
corpus.load_graph("d74eb9f1")               # разобранный граф
```

Фикстура из git всегда важнее одноимённого графа из `storage/`. До 0.8 корпусные проверки
на чистом клоне не падали, а **исчезали из сбора** (`test_t10_corpus_chain` собирался одним
пустым параметром) — набор оставался зелёным с дырой.

Тесты фиксов B5: sorted edge_key (`"B|A"` → `"A|B"`), exclude connectors из auto_bind, новый OCR-формат (B5.0). Self-contained — логика извлечена как pure functions, без PySide6.

### test_ocr_phase0.py (308 строк)

Smoke-тесты совместимости OCR-стека. Запускается внутри Docker-контейнера с GPU. Проверяет: torch+CUDA, Surya API (FoundationPredictor/RecognitionPredictor/DetectionPredictor), Surya OCR на белом изображении + кириллица, PaddlePaddle+PaddleX, PaddleOCR API, torch+paddle совместимость, наличие шрифтов.

### test_cyrillic_binding.py (370 строк)

Тесты binding с кириллическим профилем. Фаза 4: загрузка `DomainBindingConfig` + `UnifiedMatcher` (распознавание кодов Т1-ПД-585, ПД-601Р). Фаза 5: интеграция `UnifiedBinder` с фейковыми данными графа.

### test_cyrillic_load.py (330 строк)

Загрузка `domain_profile_cyrillic.yaml`. Проверяет: meta, patterns compilation, classify на всех типах кодов (FULL, HEAD, TAIL, DN, MULTI, OTHER), нормализация lat→cyr, grouping passes, noise engine, has_any_target_pattern, split_inline, has_secondary_script, загрузка через ProjectLoader.

### test_phase7_cyrillic.py (196 строк)

Сравнение `ConfigDrivenProfile(yaml)` с legacy `PidCyrillicProfile(python)`. Верифицирует, что YAML-профиль даёт идентичные результаты classify/noise/split для набора тестовых строк.

### ui/test_workspace_graph_flow.py (6 тестов)

Двухфазный графовый flow в `ui/widgets/diagram_workspace.py` — сверка по исходнику: фаза 1 открывает `SimpleGraphTab`, фаза 2 — `AdvancedGraphTab`, старый `GraphTab` не импортируется, `_on_graph_confirmed` вызывает `complete_graph_validation`. Ничего не импортирует из UI, поэтому обходится без Qt и без заглушек. Переехало из снесённого `test_stage7_graph_flow.py` (пункт 10.3): 13 его тестов держались за мёртвое окно `GraphValidationWindow` и ушли вместе с ним, ещё 5 требовали флаг `_simple_graph_done`, которого в `diagram_workspace.py` нет и не было.

### test_worker/test_imports.py (110 строк)

Smoke-тесты: все worker-задачи и утилиты импортируются без ошибок. Ловит broken imports после рефакторинга (переименование, удаление, circular imports). Проверяет: `set_diagram_error`, `check_deleted`, `upsert_artifact`, `safe_dispatch` и другие callable'ы.

### test_collection_clean.py (58 строк)

Сторож сбора (пункт 0.0): дочерним процессом проверяет, что `pytest --collect-only` чист и что набор не усох (по карте файлов базы, пункт 1-27) — дефекты уровня сессии (отравленный `sys.modules`, потерянная зависимость) внутри самой сессии не ловятся. См. §7.1.

### ui/test_gesture_dispatch.py (19 тестов)

Характеризация диспетчера мыши/клавиш графового редактора (пункт 0.4): жест подаётся настоящими `QMouseEvent`/`QKeyEvent` через публичные обработчики, проверяются только данные. Подробности и правила набора — §10.

### test_docs_match_code.py (13 тестов)

Сторож дрейфа доков (пункт 0.6): таблицы таймаутов `WORKER_TASKS.md` §4 сверяются с декораторами `worker/tasks/*.py`, а формула «OCR по умолчанию включён/выключен» в `CLAUDE.md`, `DEPLOY_README.md`, `ROADMAP_techdebt_and_agent_team.md` — с `ocr.enabled` боевого конфига. Файлы читаются как текст, боевой код не импортируется.

### test_stub_isolation.py (3 теста)

Сторож заглушек `sys.modules` (пункт 0.3x), два слоя: структурный разбирает `tests/**` через `ast` и валит любую запись в `sys.modules` **на уровне модуля** (она исполняется на сборке и живёт всю сессию); рантайм-проверка ловит подмену объявленной зависимости (`cv2`, `skimage`) в живой сессии. Правило и канон-фикстура — §6.

### test_requirements_pins.py (2 теста)

Сторож точных пинов (пункт 0.3x): версии, закреплённые через `==` и в `requirements/worker.txt`, и в `requirements/dev.txt`, обязаны совпадать. Общего файла у них нет (`dev.txt` не может тянуть `worker.txt` — там торч), поэтому `shapely` физически записан дважды и мог бы разъехаться молча: воркер на одной версии, гейт набора — на другой.

## 6. Как добавить тест

### Для нового модуля app/

1. Создать `tests/test_{module}.py`
2. conftest.py обеспечит SQLite и patched engine автоматически
3. Импортировать тестируемый модуль — env vars и patches уже применены

```python
"""Tests for app/services/my_service.py."""
import pytest
from app.services.my_service import MyService

def test_basic():
    svc = MyService()
    result = svc.process("input")
    assert result == "expected"
```

### Для нового worker task

Добавить smoke-import в `tests/test_worker/test_imports.py`:

```python
def test_my_new_task(self):
    from worker.tasks.my_task import run_my_task
    assert callable(run_my_task)
```

### Для OCR-профиля

Следовать паттерну `test_cyrillic_load.py`: загрузить YAML, создать `ConfigDrivenProfile`, проверить classify/noise/split на наборе тестовых строк с ожидаемыми результатами.

### Для UI-логики без Qt

⛔ **Не подменять `sys.modules` на уровне модуля.** Подмена без восстановления травит **всю
сессию, начиная с коллекции**: следующие файлы по алфавиту видят заглушку вместо настоящего
модуля. Проект наступал на это трижды — `test_ocr_phase0.py` (лечили `collect_ignore`),
`sys.modules.setdefault` в observability (аудит 2026-07-09, C3: 13 упавших тестов
`test_direction_nodes.py`), `_stub_qt()` на уровне модуля в `test_stage7_graph_flow.py`
(2026-08-14: `ImportError: cannot import name 'QTextLayout'` во всём `tests/ui/`; вылечено
пунктом 0.0 — заглушки переехали в фикстуру; сам файл снесён пунктом 10.3 вместе с
`ui/windows/`).

Канон — фикстура с `monkeypatch.setitem` (функциональный скоуп → авто-восстановление);
образцы: `tests/observability/test_graph_errors.py:40-51`, `test_contours_errors.py:45-56`.

Правило исполняемое, не только письменное: `tests/test_stub_isolation.py` разбирает
`tests/**` через `ast` и валится на любой записи в `sys.modules` вне функции (в том числе
спрятанной в `if`/`for` уровня модуля). Единственная разрешённая форма — приватный псевдоним
модуля-под-тестом, загруженного по файловому пути: `sys.modules[_spec.name] = mod` после
`spec_from_file_location("stats_api_under_test", …)`. Такой ключ ничего не затеняет.

Если заглушки нужны **всему файлу**, а не отдельному тесту, — фикстура `scope="module",
autouse=True`, которая сама снимает за собой: сохранить срез `sys.modules` по своим
префиксам до, восстановить после (`monkeypatch` в модульном скоупе не работает). Образец —
`tests/ui/test_bundled_fonts.py:30-51`. Запрет выше это не ослабляет: нельзя оставлять
заглушку после файла, а не «нельзя ставить её на весь файл».

Отклонение закрыто пунктом 0.3x (2026-08-18): пять файлов `tests/observability/` держали
заглушки на уровне модуля (`cv2` в четырёх, плюс подделка `skimage` и
`pipe_segmentation.inference.*`), и `tests/ui/test_bundled_fonts.py` — `ui.windows.main_window`.
Все переехали в фикстуры; 11 ошибок в `tests/ui/test_square_size_ops.py` при полном прогоне
исчезли (MEASUREMENTS §37, было — §24.9). Заглушка `cv2` при этом была не про отсутствие
зависимости: `opencv-python` объявлен в `requirements/ui.txt` и стоит и локально, и в CI —
мок просто закрывал собой настоящий модуль.

```python
@pytest.fixture
def widget_mod(monkeypatch):
    for _m in ("PySide6", "PySide6.QtCore", "PySide6.QtWidgets", "PySide6.QtGui"):
        monkeypatch.setitem(sys.modules, _m, MagicMock())
    sys.modules.pop("ui.widgets.my_widget", None)      # свежий импорт под заглушками
    mod = importlib.import_module("ui.widgets.my_widget")
    yield mod
    sys.modules.pop("ui.widgets.my_widget", None)      # ноль протечки
```

Логику методов тестировать через `patch`, виджеты — `MagicMock`.

## 7. Базовая линия, маркеры и CI

Добавлено пунктом 0.3 дороги рефакторинга (2026-08-17).

### 7.1 Базовая линия набора

Набор красный не весь: на 2026-08-18 из 871 собранного **46 красных** (37 failed + 9 errors),
и падают они своими причинами, а не текущей работой. Поэтому гейт — не «ноль красных», а
**«ни одного нового красного»**. Список зафиксирован в git: `tools/bench/suite_baseline.json`.
(Было 57 при 738 собранных: 11 ошибок в `tests/ui/test_square_size_ops.py` оказались не
дефектом теста, а чужой заглушкой `cv2` — снято пунктом 0.3x, §6.)

Стенд запускает pytest дочерним процессом с `-X utf8` принудительно: замерено, что под
cp1251 `test_refactoring.py:697` (`read_text()` без `encoding`) падает с `UnicodeDecodeError`,
а под UTF-8 тот же тест зелёный. База обязана быть одинаковой на любой машине, поэтому
режим кодировки задаёт стенд, а не консоль. Прямой `pytest -q` под cp1251 даст на один
красный больше — это не регрессия, а кодировка.

```bash
# сверить прогон с базой (exit 1 при новом красном или усыхании набора)
python -X utf8 tools/suite_baseline.py --check

# пересъём базы — ТОЛЬКО отдельным коммитом с объяснением (Д6)
python -X utf8 tools/suite_baseline.py --write-baseline
```

Единичный позеленевший тест провалом не считается — стенд печатает его и просит пересъём.
Разбор 57 красных по корням — `MEASUREMENTS.md §25`; чинить их — отдельные пункты дороги.

**Что валит гейт, кроме нового красного** (добавлено по ревизии 0.3 — гейт был зелёным на
убитом прогоне):

| проверка | зачем |
|---|---|
| код возврата pytest вне `{0, 1}` | `os._exit`, access violation (§24.6), ошибка вызова: красных разобрано ноль, и без проверки это читается как «всё починилось» |
| нет итоговой строки / `failed + errors` не сходится с числом разобранных id | вывод оборван на середине |
| позеленело больше `MAX_FIXED` (10) | так выглядит обрезанный прогон; настоящая починка такого объёма обязана пересъёмкой объяснить себя |
| `skipped` вырос на прогоне, где что-то позеленело | красный тест превратили в `skip` — это не починка |
| тесты пропали у файлов, которых в диффе не трогали | набор усох (см. ниже: считается по карте файлов, корпусные параметры вне git в неё не входят) |

`PYTEST_ADDOPTS` у дочернего pytest выпалывается: `-x`/`-k` из окружения родителя обрезали бы
прогон.

**Пересъём не легализует новых красных** (пункт 1-26). До него `--write-baseline` предыдущую
базу вообще не читал: проверял код возврата и наличие итоговой строки, после чего перезаписывал
`red` тем, что красно сейчас. Сверка жила только в `--check`, а пересъём по Д6 идёт **отдельным
коммитом** — то есть красный флаг №4 протокола («эталон изменён тем же коммитом, что и код»)
его не видит. Дыра проверена в лоб: на подложенном красном тесте стенд писал «база записана:
4 красных» вместо 3 и молча узаконивал регрессию.

**Пересъём не легализует и потерю тестов** (пункт 1-28). Вторая половина той же дыры:
`cmd_write` не смотрел на ПОЛ набора вовсе. Замерено 2026-08-19 — `collect_ignore` каталога
унёс 147 тестов (файлы при этом байт-в-байт те же), стенд отдал **exit 0** и записал пол
**952 → 811** с картой **89 → 64** файлов; состав красных не изменился, поэтому сверка 1-26
промолчала, а следующий `--check` на здоровом дереве был зелёным — потеря стала нормой.
Теперь пересъём судит тем же `floor_problems`, что и `--check`: третий потребитель одного пола.
⚠ Сторож `test_collection_clean.py::test_suite_does_not_shrink` заменой стенду не был: он сам

**Три исхода вместо двух** (пункт 1-28, `PROTOCOL §5`). До него «судить нечем» и «отказ»
отдавали одинаковый код 1, и вызывающий не мог отличить «чини обстановку» от «чини код».

| исход `--write-baseline` | когда |
|---|---|
| **ОТКАЗ, exit 1** | в прогоне есть красный, которого нет в базе (`[ОТКАЗ] множество красных выросло…` + список новых) |
| **ОТКАЗ, exit 1** | набор тихо потерял тесты: файлы в диффе не менялись, а тестов из них меньше (`[ОТКАЗ] набор усох: тихо потеряно N…`) |
| **СУДИТЬ НЕЧЕМ, exit 2** | сбор pytest сломан (это пункт 0.0, а не база) |
| **СУДИТЬ НЕЧЕМ, exit 2** | прогон убит: pytest вернул код вне `{0, 1}`, или нет итоговой строки |
| **СУДИТЬ НЕЧЕМ, exit 2** | вывод неполон: `failed + errors` не сходится с числом разобранных id — на оборванном хвосте рост состава невидим |
| пересъём, exit 0 | красные ушли (тесты починили) |
| пересъём, exit 0 | состав красных тот же, изменилось `collected`/`totals` — рядовой Д6-пересъём пункта дороги |
| пересъём, exit 0 | потерю видно в диффе: файл снят вместе с записью о нём в git — откат пункта |
| пересъём, exit 0 | базы в дереве нет: первый снимок сверять не с чем, и стенд об этом печатает строку |

У `--check` код возврата не менялся: там «сбор сломан» по-прежнему exit 1, потому что шаг CI
на этом стенде 1 и 2 не различает.

Новый красный чинят или откатывают. Способа «переписать эталон и поехать дальше» у стенда нет
намеренно: единственная лазейка обратно — удалить `tools/bench/suite_baseline.json`, а это видно
в диффе. ⚠ Следствие на волну 13: переезд файлов переименует id красных тестов, и пересъём
откажет законно — решение об этом принимает архитектор, а не исполнитель.

**Усыхание набора.** `tests/test_collection_clean.py` проверяет две вещи дочерним процессом:
сбор без ошибок (exit 0) и что набор не усох. Арифметика общая со стендом
(`suite_baseline.floor_problems`) — два потребителя одного пола не должны разъехаться.

**Откат пункта — не усыхание** (пункт 1-27). Пока пол был одним числом, `git revert` пункта
ронял его законным образом: пункты дороги приносят по 5–53 теста (3.x1 +3, 1.2 +6, 1.10 +17,
0.4 +19, 0.11 +21, 0.5 +53) при запасе 5, а после ближайшего Д6-пересъёма их тесты уже входят
в пол. Замерено 2026-08-19 на копии дерева: `git revert` тега `road-ГЕЙТ-1` → «набор усох:
в git-видимой части 936 < 942», exit 1 — то есть тег переставал быть точкой возврата,
как обещает `PROTOCOL §6`.

Теперь база несёт **карту файлов** `per_file` — `{файл: [сколько git-видимых тестов, отпечаток
файла]}`, — и потеря разбирается по ней:

| что случилось с файлом | как судится |
|---|---|
| файл на месте, отпечаток тот же, тестов меньше | **усыхание** — в диффе не видно ничего (`importorskip` без зависимости, `collect_ignore`, сломанный `conftest`) |
| файла нет, и git его больше не числит | откат пункта — вычитается из счёта и печатается строкой |
| файл правили (отпечаток разошёлся) | видно в диффе, судит ревизор — вычитается и печатается |
| файла нет, а git его числит | **усыхание**: стёрт или переименован мимо git |
| git не ответил про пропавшие файлы | провал: об откате судить нечем |

Отпечаток берётся с нормализованными переводами строк: у машины разработки checkout с CRLF,
у раннера с LF, и без нормализации в CI «изменённым» выглядел бы каждый файл — а изменённому
файлу потеря прощается, то есть пол ослеп бы целиком.

⛔ Расширять `FLOOR_MARGIN`, чтобы «пропустить откат», нельзя: запас, перекрывающий откат
(до 53 тестов), ослепил бы гейт ровно на эту величину. Откат считается отдельно, запас
остаётся 5 и покрывает только тихую потерю.

**Пол считается от git-видимой части сбора** (пункт 0.3y). Вся разница «машина разработки ↔
раннер» — это параметризация `test_canvas_pipeline_golden.py::test_t10_corpus_chain` по корпусу
из локального `storage/` (загрузчик КД7, §3). Такие параметры из счёта вычитаются: их uid8 нет
в `tests/fixtures/graph/`, значит на чистом дереве их не бывает. В базе лежат оба числа —
`collected` и `collected_git_visible`, плюс `corpus_local` (сколько вычли).

Почему не «просто побольше запас»: пол снимается на машине разработки, и, пока корпус входил в
счёт, он ехал вверх от каждой новой диаграммы в `storage/` — то есть от чужих прогонов
конвейера, а не от правок. Замерено 2026-08-18 (пункт 0.3y): три добавленные диаграммы дают
собрано 879 при неизменных **860** git-видимых; по старой формуле пол стал бы **861** — выше
того, что раннер вообще способен собрать, то есть ЛОЖНЫЙ красный «набор усох». По новой пол
**855** и не двигается.

Запас (`FLOOR_MARGIN`) после этого сжат с **18 до 5**: перекрывать корпусную разницу он больше
не обязан (git-видимых 855 и локально, и в CI — разница 0), а мелкие потери ловить обязан.
5 вчетверо уже 22 тестов раскладки, которые молча уходят без `shapely` (`importorskip`):

выдают 3 новых красных в `test_client_spec.py`.

## 8. Линтеры и воспроизводимость раскладки

Добавлено пунктом 0.10 дороги рефакторинга (2026-08-18): требования **ПР5** и **ПР1**
мастер-плана. Оба стенда сделаны по контракту §7.1 — эталон в git, `--check` → exit 1,

### 8.1 Конфиг линтеров и храповик долга

`ruff` и `mypy` стояли в `requirements/dev.txt` с самого начала, но конфига не было
ни одного (`pyproject.toml`, `ruff.toml`, `mypy.ini`, `setup.cfg` — ничего), то есть
они не запускались. Конфиг теперь в `pyproject.toml`; секций `[project]`/`[build-system]`
там намеренно нет — пакетом проект не собирается.

Выбрано **одно** правило: `BLE001` (`except Exception`) и `E722` (голый `except:`) — это
одна и та же болезнь, «широкий перехват». Замер 2026-08-18: **199 нарушений в 73 файлах** — считаются только файлы под git (мусор рабочего дерева иначе разводит счётчик машины и раннера и заранее прощает долг файлу, которого в git ещё нет).
Оплатить их одним коммитом нельзя, а `ruff check` на таком долге красен всегда и гейтом
быть не может. Поэтому судит **храповик**:

```bash
# долг по файлам не вырос + mypy на своём списке чист (exit 1 при росте)
python -X utf8 tools/lint_gate.py --check

# пересъём эталона — ТОЛЬКО отдельным коммитом с объяснением (Д6)
python -X utf8 tools/lint_gate.py --write-baseline

# посмотреть сам долг
python -m ruff check --statistics
```

Эталон — `tools/bench/lint_baseline.json`: счётчик нарушений **на каждый файл**. Провал —
рост в любом файле, в том числе уже грязном (per-file-ignores такое пропускают, поэтому их
и нет). Оплата долга печатается и гейт не валит. Пустой результат при непустом эталоне и код
возврата линтера вне `{0, 1}` — тоже провал: убитый прогон не имеет права выглядеть зелёным
(тот же класс дефекта, что блокер пункта 0.3).

**Пересъём не легализует долг** (пункт 1-28). До него `--write-baseline` не читал эталон
вовсе — `read_baseline()` звался только в ветке `--check`. Замерено 2026-08-19: широкий
`except` в чистом `tools/corpus.py` красил `--check` (`0 -> 1`, exit 1), после чего один
`--write-baseline` (эталон 178 → 179, **exit 0**) делал `--check` снова зелёным. Пересъём
идёт отдельным коммитом, как требует Д6, поэтому красный флаг №4 протокола этого не видит.

| исход `--write-baseline` | когда |
|---|---|
| **ОТКАЗ, exit 1** | долг вырос хотя бы в одном файле — список `файл: было -> стало` |
| **СУДИТЬ НЕЧЕМ, exit 2** | ноль нарушений при непустом эталоне: прогон ruff убит, пересъём записал бы пустой долг |
| пересъём, exit 0 | долг не вырос (в том числе оплачен) |
| пересъём, exit 0 | эталона в дереве нет — первый снимок |

Грязный `mypy` пересъём **не** блокирует намеренно: в файл эталона пишется только счёт ruff,
и пересъёмом долг mypy не легализуется — его судит `--check` на каждом прогоне.

Как писать новый широкий перехват, если он осознан, — идиома в проекте уже есть
(10 мест на 2026-08-18):

```python
except Exception as exc:  # noqa: BLE001 — брокер может быть недоступен
```

`mypy` идёт **по включению**: список `files` в `pyproject.toml` — то, что проходит начисто
(`follow_imports = "silent"`, `ignore_missing_imports = true`: стабов для torch/cv2/PySide6
нет и не будет). Ноль ошибок на этом списке — требование, а не эталон. Новый модуль автор
дописывает в список сам; разворачивать mypy на весь репозиторий — работа этапов 12–13.
`modules/canvas_to_fxml.py` в список не попал: 7 своих ошибок, правка — чужой пункт.

### 8.2 Воспроизводимость раскладки (ПР1)

`tools/cmp_bitexact.py` — главный критерий «рефакторинг не изменил поведения»: сравнение
выхода `layout()` с эталоном **бит-в-бит**. На недетерминированном графе такой критерий
краснеет ложно. Стенд отвечает числом:

```bash
# весь доступный корпус (фикстуры из git + локальный storage), два прогона
python -X utf8 tools/layout_determinism.py

# то, что видит CI
python -X utf8 tools/layout_determinism.py --git-only --runs 10 --check

# локализация: та же проверка без этапа роутинга
python -X utf8 tools/layout_determinism.py --uid 6e7144d5 --runs 30 --no-routing
```

Каждый прогон — **отдельный процесс** со своим `PYTHONHASHSEED`: так ловится и обход множеств
строк, и всё, что зависит от состояния кучи. Сравнивается sha256 от `json.dumps(graph)` —
та же проекция, что у `cmp_bitexact`.

⚠ **Замерено 2026-08-18: раскладка воспроизводима НЕ ВСЯ — 8 графов корпуса из 17.**
Недетерминизм локализован в этапе роутинга (`LayoutParams.routing`, обход чужих форм
через vendored libavoid):

| что замерено | результат |
|---|---|
| полный корпус, два независимых замера по 6 прогонов | **8 из 17 неповторимы**: `0aea61c0`, `302171b3`, `54a60fd1`, `620cc50d`, `6e7144d5`, `751116c9`, `a5264536`, `a6d28736`. Первый замер нашёл семь, второй — восьмого (`620cc50d`); у `a5264536` доходило до 6 разных исходов на 6 прогонов |
| ⭐ **гуляет ли качество** — число дефектов на тех же восьми, 6 прогонов | **нет**: у каждого графа дефекты одни и те же во всех прогонах (`156 -> 11`, `13 -> 0`, `70 -> 4`, `51 -> 0`, `14 -> 0`, `44 -> 0`, `34 -> 0`, `128 -> 7`). Меняется геометрия, не качество |
| `layout()` с роутингом, 30 прогонов на `6e7144d5` | **2 разных исхода** |
| то же **без** роутинга, 30 прогонов | 1 исход — воспроизводимо |
| пины (наш вход в libavoid), 20 прогонов | 1 исход — наш код детерминирован |
| сырые маршруты libavoid на одном и том же входе, 30 прогонов в ОДНОМ процессе | **2 исхода** |

То есть источник — сам `vendor/adaptagrams`, а не питоновский код: `PYTHONHASHSEED` и адрес
объекта `Router` с исходом не коррелируют, ни одна из пяти опций нуджинга libavoid его не
убирает. Расходится выбор, какому из двух равноправных рёбер достанется обход; число дефектов
у обоих исходов одинаковое.

Эталон `tools/bench/determinism_baseline.json` фиксирует **по графам**, что воспроизводимо
сегодня. Провал `--check` — граф, который был воспроизводим, перестал им быть (или новый граф
корпуса неповторим). Обратное движение печатается, гейт не валит.

⛔ **Третий исход, добавлен пунктом ГЕЙТ-1 (2026-08-19): `exit 2` — «судить нечем».**
Эталон покрывает 17 графов, в git лежат 3 — и до ГЕЙТ-1 прогон на усечённом корпусе
печатал `[OK] регресса воспроизводимости нет` и отдавал **exit 0**, ни разу не тронув
14 остальных (8 известных неповторимых среди них). Теперь `set(эталон) - set(измеренного)`
не пуст → `[СУДИТЬ НЕЧЕМ] не измерено N графов эталона` и **exit 2**; вердикт по корпусу
выносит только полный локальный прогон. Доказанный регресс сильнее неполноты: если
сломался измеренный граф — это по-прежнему exit 1. Шаг CI различает 1 и 2: на 2 он пишет
`::warning` «стенд не судит» и сборку не роняет (`PROTOCOL §5`, `.github/workflows/tests.yml`).
Тем же пунктом чинится `tools/edit_bench.py`: его корпус лежит вне git (`.gitignore:37`),
и замер части корпуса тоже больше не читается как «дефекты не выросли».

⛔ **Пересъём судит по тем же трём исходам (пункт 1-28).** ГЕЙТ-1 закрыл только `--check`,
а меняет эталон именно запись. Замерено 2026-08-19: `--git-only --runs 2 --write-baseline`
печатал «эталон переснят», отдавал **exit 0** и оставлял в файле **3 графа вместо 17** —
вместе с восемью известными неповторимыми; заодно `runs` в эталоне уезжал с 6 на 2.

| исход `--write-baseline` | когда |
|---|---|
| **ОТКАЗ, exit 1** | граф, который эталон числит воспроизводимым, сломался — пересъём записал бы поломку нормой |
| **СУДИТЬ НЕЧЕМ, exit 2** | часть графов эталона не измерена (корпус усечён) — пересъём вычеркнул бы их |
| **СУДИТЬ НЕЧЕМ, exit 2** | `--runs` меньше, чем у эталона: замер слабее того, что заменяет (пункт 1-29) |
| **СУДИТЬ НЕЧЕМ, exit 2** | `--no-routing` против `routing: true` в эталоне: замер другой величины (пункт 1-29) |
| пересъём с оговоркой, exit 0 | замер дал один хеш на графе, который эталон числит неповторимым: `false` **сохранён**, строка `[ВЫБОРКА, НЕ ПОЧИНКА]` (пункт 1-29) |
| пересъём починки, exit 0 | то же, но граф назван в `--allow-fixed`: записывается `true`, строка `[ПОЧИНКА]` — объяснение обязано быть в коммите |
| пересъём, exit 0 | измерен весь эталон и ни один воспроизводимый граф не сломался |
| пересъём, exit 0 | эталона в дереве нет — первый снимок |

⛔ **Пересъём не имеет права быть слабее эталона (пункт 1-29).** Замерено 2026-08-19
(§49.27): пересъём при `--runs 2` записал `true` **четырём из восьми** известных
неповторимых графов (`54a60fd1`, `620cc50d`, `6e7144d5`, `751116c9`) — эталон снят при
`runs 6`, и одна удачная выборка вычеркнула бы половину списка молча. Отказ 1-28 такого
не ловит по замыслу: `false -> true` — законное «стало лучше» (так же судит и `--check`).
Поэтому стережётся сам замер: `--runs` меньше эталонных или другой ключ роутинга — это
**«судить нечем»**, а не «эталон переснят». Число прогонов в эталоне работает храповиком:
пересъём при `--runs 8` записывает 8, и следующий судится уже по восьми. Ключ роутинга
опасен сильнее числа прогонов: без роутинга раскладка воспроизводима **вся** (недетерминизм
целиком в libavoid), так что `--no-routing --write-baseline` стёр бы список неповторимых
разом — одной командой, отдельным коммитом по Д6, мимо красного флага №4.

Отказ на сломавшемся графе снимается тем же путём, что описан ниже: повторный прогон
с бо́льшим `--runs`, разбор причины и пересъём вместе с объяснением, ЧТО изменилось в коде.

⛔ **«Стало лучше» на графе из списка неповторимых — это почти всегда удачная выборка,
а не починка.** Замерено: `0aea61c0` в двух замерах неповторим, в третьем дал один хеш.
Неповторимость — наблюдение положительное, и одна тихая серия его не отменяет: переснимать
эталон в сторону «воспроизводим» можно только вместе с объяснением, ЧТО в коде изменилось.

⛔ **С пункта 1-29 это правило стережёт стенд, а не только человек.** Проверять было чем:
пересъём 1-29 на полном корпусе при `--runs 6` — том самом поле, который тот же пункт и
ввёл, — снова дал `0aea61c0` с одним хешем и записал его `true` (§50.19). То есть пол по
числу прогонов необходим, но недостаточен: у графа с редким расхождением шесть прогонов
ловят не всегда. Теперь `false` в эталоне **липкий** (`merge_stable()`): замер, показавший
один хеш там, где эталон помнит расхождение, его не стирает — печатается
`[ВЫБОРКА, НЕ ПОЧИНКА]` и в файл уходит прежний `false`. Снять его может только явно
названная починка:

```bash
python -X utf8 tools/layout_determinism.py --runs 6 --write-baseline --allow-fixed 0aea61c0
```

Ключ и есть то самое «объяснение»: он заставляет назвать граф руками и сказать в коммите,
ЧТО изменилось в коде. Без него храповик стал бы вечным — починку недетерминизма libavoid
(ВН3, волна 9) записать было бы нечем.

⚠ Гейт по своей природе **выборочный**: неповторимость доказывается наблюдением двух исходов,
а воспроизводимость — только ненаблюдением расхождения за N прогонов. Отсюда `--runs 10`
в CI на дешёвых графах и `--runs 6` для эталона по всему корпусу. Значит «воспроизводим»
в эталоне читается как «за 6 прогонов не поймали», и **`[ПРОВАЛ] перестал воспроизводиться`
на крупном графе может означать не регресс кода, а более удачную выборку**. Разбирать такой
провал надо повторным прогоном с большим `--runs`, а не откатом правки; двух-трёх исходов
там, где раньше был один, достаточно, чтобы переснять эталон (Д6).

Полный корпус — это ~30 минут (17 графов × 6 прогонов; один `51b339ab` считается 72 с).
Рабочий режим — `--git-only`; полный прогон обязателен на пунктах, трогающих
`modules/graph/` или canvas-путь, там же, где обязателен полный корпус по замеру 0.8.

**Что из этого следует для гейтов дороги.** `cmp_bitexact` как критерий «бит-в-бит»
на этих восьми графах не работает и работать не начнёт, пока недетерминизм в libavoid жив:
рефакторинг там доказывается либо сравнением с `--no-routing` (бит-в-бит, 30 прогонов из 30
стабильно), либо инвариантами. Инварианты для этого годятся — замерено, что **счётчики
дефектов не гуляют**, то есть `layout_bench` и приёмка «не хуже входа» шумом не задеты.
Источник — чужой бинарь (`vendor/adaptagrams`), правка живёт не в этом пункте: разведка
библиотеки уже стоит в очереди отдельным пунктом (волна 9, ВН3).

⚠ Не проверено вовсе: бой считает раскладку в Linux-контейнере со своим `_adaptagrams.so`,
все замеры выше сняты на win-бинаре. Совпадение байт-в-байт **между платформами** — открытый
вопрос той же природы, что «Linux-прогона тестов нет» (§7.3).

## 9. Стенд диффов «до/после оператора» (ДН4)

Добавлен пунктом 0.11 дороги рефакторинга (2026-08-18) — «слой 0» плана сбора статистики
(`docs/planning/PLAN_2026-08-13_stats_collection.md` §3). Конвейер построен вокруг человека
в цикле, поэтому на каждом ручном этапе на диске лежат две версии одного артефакта:
машинная и та, что оператор оставил после правки. Разница между ними — цена ошибок модели,
уже записанная и никем не читаемая.

```bash
# таблицы по семи парам + медианы «объёма правок»
python -X utf8 tools/pair_bench.py

# одна пара (только отчёт: эталон и --check работают по всем парам сразу)
python -X utf8 tools/pair_bench.py --stage graph

# заморозить эталон — ТОЛЬКО отдельным коммитом с объяснением (Д6)
python -X utf8 tools/pair_bench.py --write-baseline

# сравнить с эталоном: exit 1 при росте правок, exit 2 когда судить нечем
python -X utf8 tools/pair_bench.py --check
```

Семь пар: `detection` (yolo_predicted → yolo_validated), `segmentation`
(pipe_mask → pipe_mask_validated), `junction` (points → points_validated), `graph`
(graph → graph_validated), `contours` (contours_auto → contours_validated), `ocr`
(ocr_result → ocr_binding), `layout` (graph_validated → graph_canvas). Колонки со звёздочкой —
«объём правок», только они судятся; остальные справочные. Числа первого замера —
`MEASUREMENTS.md` §33.

**Стенд НЕ в CI, и это не забывчивость.** `storage/diagrams/` в git нет (данные заказчика,
решение плана — в git поехали только три графа, §7.1 и пункт 0.8), поэтому на раннере мерить
нечего. `--check` там честно возвращает **2** («ни одной пары не найдено»), а не зелёный ноль:
пустой прогон, выглядящий как успех, — тот же класс дефекта, что блокер пункта 0.3. В CI идут
юнит-тесты стенда (`tests/test_pair_bench.py`, 21 тест на синтетических артефактах).

**Чего числа стенда НЕ значат** (все четыре оговорки замерены, а не предположены):

- **Тождество объектов.** `id` есть только у графа; боксы, точки и текстовые блоки
  сопоставляются геометрически. Сильно переставленный объект читается как «удалён +
  добавлен» — это занижает «сдвинут», а не завышает общий объём.
- **Порядок пары.** Если файл «до» новее файла «после», стадию перезапустили ПОСЛЕ правки
  оператора: пара помечается `!`, её числа — не правки. Замер 2026-08-18: 4 пары `layout`
  и 2 пары `ocr` из 106.
- **Сдвиг начала координат.** Не сопоставилась половина набора, а остаток объясняется одним
  общим смещением — стенд печатает `origin_shift` в пикселях: стороны пары сняты на разных
  обрезках листа (`8d14cf73`: +26/−21 px), «правки» там мнимые.
- **Раскладка координаты не сравнивает** вовсе: холст и валидированный граф живут в разных
  системах координат. Пара `layout` считает только состав и число объектов с флагом `manual`.

## 10. Характеризационные тесты жестов редактора

Добавлены пунктом 0.4 дороги рефакторинга (2026-08-18) как **сетка безопасности** под
декомпозицию UI (этап 10) и структурные победы 0.5: на диспетчер мыши графового редактора
(`BaseGraphEditor.mousePressEvent/mouseMoveEvent/mouseReleaseEvent` +
переопределения `AdvancedGraphEditor`) не было ни одного теста. Соседние наборы
(`tests/ui/test_interactive_drag.py`, `tests/ui/test_mode_exit_finishes_gesture.py`)
дёргают ВНУТРЕННИЕ методы жеста (`start_drag_node`/`drag_node_to`/`end_drag_node`,
`on_exit` хендлера), то есть проверяют исполнителя, а не того, кто раздаёт клики.

```bash
# весь набор (Qt offscreen ставится самим файлом, отдельного окружения не нужно)
python -X utf8 -m pytest tests/ui/test_gesture_dispatch.py -q

# все UI-тесты
python -X utf8 -m pytest -m ui -q
```

**Правило набора: утверждения только о ДАННЫХ.** Проверяются геометрия узлов
(`bbox`/`centroid`/`segmentation`), состав узлов и рёбер, глубина стека undo и число
ВИДИМЫХ ручек размера на сцене. Ни одного утверждения про `_current_mode`,
`_current_handler`, `_ctrl_lmb_*` — иначе половина набора умрёт вместе с
`simple_handlers.py` на этапе 10 и перестанет что-либо доказывать ровно тогда, когда
понадобится. Ручки считаются сканом сцены (квадрат `HANDLE_SIZE` на слое `HANDLE_Z`),
а не через поле `_resize_overlay`: так проверка переживёт перенос ресайза с режима на
оверлей (пункт 10.1).

Что зафиксировано: клик против протяжки с двух сторон порога (2 px — клик, 10 px — уже
протяжка; сегодня `DRAG_THRESHOLD` = 5); снятие защёлки `ctrl_pressed` первым же ЛКМ без
Ctrl (защёлка переживает alt-tab); обрыв «залипшего drag» кадром движения с отпущенной
кнопкой и по потере фокуса; удаление узла Ctrl+ПКМ вместе с инцидентными рёбрами и возврат
обоих по Ctrl+Z; уход клика инструменту вместо узла при активном инструменте; расширение
выделения Ctrl-кликом по телу рамки и по ребру; групповая протяжка одной дельтой на всё
выделение; появление/исчезновение четырёх ручек размера и правка рамки за угол.

Три ловушки, замеренные при написании (`MEASUREMENTS.md` §36) — учитывать в новых тестах:

- **Координаты двойственны** (`CODING_GUIDE.md` §6): `centroid` = `[y, x]`,
  `bbox` = `[x1, y1, x2, y2]`, сцена — `(x, y)`.
- **`mapFromScene` отдаёт ЦЕЛЫЙ пиксель вьюпорта**, а масштаб вида в тесте ≈ 0.33 —
  обратный перевод даёт до ~1.2 px расхождения по сцене. Поэтому сдвиги сверяются с
  допуском (`DRAG_TOL` = 4 px), а побайтово сравнивается только то, что вернул undo.
- **Защёлка `ctrl_pressed` — состояние клавиатуры.** Ветки расширения выделения в
  `AdvancedGraphEditor.mousePressEvent` читают её ДО того, как базовый класс обновит её из
  модификаторов события: клик с модификатором Ctrl, но без предшествующего `KeyPress`
  Ctrl, в эти ветки не попадает. Оператор Ctrl держит — тест обязан делать так же.

Данные — корпус-фикстура `d74eb9f1` из git (`tools/corpus.py`, пункт 0.8) плюс белый растр
её размера, поэтому набор идёт и в CI, и на чистом клоне. Редакторы масок
(`square_mask_editor`, `polyline_mask_editor`) этим набором НЕ покрыты: их геометрия идёт
через `cv2`, замоканный на уровне модуля в `tests/observability/` — до пункта 0.3x такие
тесты в полном прогоне красные не по своей вине (см. §5).
