# ADR-002: LoRA rank r=8

**Статус:** Принято  
**Дата:** 2025-12  
**Контекст:** Выбор rank для LoRA fine-tune SAM2

---

## Контекст

LoRA добавляет trainable low-rank матрицы A (r × in) и B (out × r) к каждому Linear слою SAM2 с ≥ 64 features. Rank определяет количество trainable параметров и ёмкость адаптации.

## Эксперимент

Обучены 4 модели с r=4, 8, 16, 32 на одном датасете (915 samples) с идентичными гиперпараметрами:

| Rank | Trainable params (approx) | Результат |
|------|--------------------------|-----------|
| r=4 | ~0.5M | В пределах 1.3% от лучшего |
| r=8 | ~1M | В пределах 1.3% от лучшего |
| r=16 | ~2M | В пределах 1.3% от лучшего |
| r=32 | ~4M | В пределах 1.3% от лучшего |

Все варианты показали результаты в пределах шума — разница не превышает 1.3%.

## Решение

r=8 (alpha=16, scale=2.0).

## Обоснование

1. **Bottleneck — данные, не ёмкость.** При 915 samples даже r=4 достаточно. Увеличение rank не улучшает метрики.
2. **Баланс.** r=8 — стандартный выбор в литературе, достаточная ёмкость для потенциального расширения датасета, при этом checkpoint остаётся маленьким (~5 MB).
3. **GPU memory.** r=8 добавляет минимальный overhead по сравнению с r=4, но при росте датасета не потребуется переобучение.

## Последствия

- При росте датасета до ~5000+ samples стоит повторить эксперимент — возможно, r=16 покажет преимущество.
- Rank хранится в checkpoint config (`ckpt['config']['lora_r']`) — при загрузке используется автоматически.
