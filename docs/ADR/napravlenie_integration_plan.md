# План интеграции: класс `napravlenie` (стрелка направления на трубе)

> Хэндофф для реализации в новой сессии. Ознакомление и выверка маппинга уже сделаны —
> здесь зафиксированы все находки и решения, чтобы ничего не потерять.

## Проблема

Появился класс `napravlenie` — стрелка направления, стоящая **на** трубе (труба
проходит сквозь её bbox). Для графа прохождение трубы сквозь бокс — это **правильно**.

Сейчас бокс ломает и сегментацию, и граф:
- **Сегментация** (`worker/tasks/segmentation.py::generate_node_mask`) делает узлом
  всё, кроме `truba`/`annotation` (фильтр по имени). Значит бокс `napravlenie`
  вырезается из `pipe_mask` и затем раздувается постобработкой → труба пропадает,
  коллизии с соседними трубами.
- **Граф** (`modules/graph/core/nodes.py::prepare_tracing_data`, ~строки 711–720)
  стирает скелет внутри раздутого bbox узла перед трассировкой → ребро обрывается
  у границы бокса, вместо того чтобы идти насквозь.

## Маппинг классов (выверено)

Две системы нумерации, согласованы через `+1`:
- Внутренние YOLO `class_id` (используются в `nodes.py::CLASS_NAMES`):
  `truba=36, strelka=38, napravlenie=40, annotation=34, background=39`.
- CVAT `category_id` в coco-файлах и `thermohydraulics.yaml` (= `class_id + 1`):
  `truba=37, strelka=39, napravlenie=41`.
- `nodes.py:156` делает `class_id = category_id - 1` → системы совпадают.

Текущее поведение:
- Граф: `EXCLUDED_CLASS_IDS = {34, 36, 38, 39}` → `strelka(38)` исключён,
  `napravlenie(40)` **НЕ** исключён → именно он сейчас рвёт ребро.
- Сегментация фильтрует по имени → `napravlenie` и `strelka` оба вырезаются.

## Решения (подтверждены пользователем)

1. Классификация направления — **отдельный worker-шаг после детекции**, пишет поле
   `direction` в `coco_validated.json` (единый источник правды для сегментации и графа).
2. Перпендикулярная труба, пересекающая бокс, **остаётся своим ребром**, но НЕ
   соединяется со «стрелочной» трубой через бокс.
3. `strelka` — **оставить как есть** (правим только `napravlenie`).
4. Если труба под боксом всё же рвётся — дотягивать по точным границам из «Контур»
   (SAM2, `worker/tasks/contours.py::task_extract_contours`).
5. **`napravlenie` — это УЗЕЛ графа, а не атрибут ребра** (иначе терминальное ребро,
   упирающееся в стрелку, теряет конечную точку и выпадает при сборке; FXML не на чём
   якорить). Тип узла — новый `type: "direction"` (рядом с `equipment/connector/junction`).

### Дизайн узла `direction`

- **Inline-узел на трубе**, не оборудование и не junction. Степень обычно 2 (вход/выход
  по оси стрелки), допускается 1 — терминальная стрелка.
- **Ориентация:** поле `direction` (up/right/down/left от классификатора) задаёт вход/выход
  и штампует направление потока на инцидентные рёбра. Граф сейчас НЕнаправленный
  (нет `DiGraph`) — это единственный источник локальной направленности.
- **Порты только по оси стрелки = правило стороны:** для direction-узла `contact_map`
  (`nodes.py`) эмитится ТОЛЬКО на двух гранях вдоль оси стрелки. Перпендикуляр касается
  верх/низ-грани → не попадает в `contact_map` → не цепляется → остаётся своим ребром.
- **Сегментация развязана:** в `node_mask` стрелку НЕ вносим (труба выживает на pipe_mask/
  скелете); узлом она становится только на этапе графа (бокс стирается штатно, сшивается
  через два осевых порта).
- **FXML** (`modules/graph_to_fxml.py`): тип `direction` → символ стрелки направления
  ЛИБО «схлопывание» узла в одно направленное звено трубы с сохранением ориентации.
  Решить при реализации по схеме FXML; узел есть в любом случае → ничего не теряется.

### Существующая почва в коде

- Типы узлов: `equipment`, `connector`, `junction`, `invalid_bridge` (`nodes.py`,
  `export_json.py:71,130,189`). Новый `direction` встраивается сюда.
- Граф ненаправленный (в `builder.py` нет `DiGraph`/direction) — направленность новая.
- FXML строит `modules/graph_to_fxml.py`.

   **ВАЖНО: node_mask генерится В ДВУХ местах** — `worker/tasks/segmentation.py::generate_node_mask`

   нового типа `type: "direction"` (НЕ исключать из узлов, НЕ делать equipment).
   Бокс стирается штатно; труба входит/выходит через два осевых порта. Направление
   из coco штампуется на инцидентные рёбра. Терминальная стрелка (степень 1) валидна.

   эмитить ТОЛЬКО на двух гранях вдоль оси стрелки (вправо → левая/правая). Перпендикуляр
   касается верх/низ → не в `contact_map` → остаётся своим ребром. Доп. проверка через
   `bbox_exit_side` / `determine_exit_direction`.
5b. **FXML** (#8): в `modules/graph_to_fxml.py` обработать новый `type:"direction"`
    (символ стрелки или направленное звено). Сверить со схемой FXML.
5. **Тесты** (#6): сквозная проверка на примере из `storage/diagrams/` — труба под

   не слился.
