# ADR-005: Smart snap для регуляризации полигонов

**Статус:** Принято  
**Дата:** 2026-01  
**Контекст:** Постобработка масок SAM2 для получения инженерных полигонов

---

## Контекст

SAM2 выдаёт пиксельную маску (1024×1024 binary). Для FXML-экспорта и работы в САПР нужны полигоны с ровными горизонтальными/вертикальными рёбрами — типичная геометрия символов P&ID (прямоугольники, трапеции, стандартные формы ISO/ISA).

## Рассмотренные альтернативы

**Только Douglas-Peucker.** Стандартная полигонализация контура. Результат: полигон с меньшим числом точек, но рёбра "почти горизонтальные" (отклонение 2–5°) — выглядит неряшливо в САПР.

**Convex hull / minimum bounding rectangle.** Слишком грубо — теряется форма сложных символов (теплообменники, сепараторы).

**Douglas-Peucker + H/V edge snapping** (smart snap). DP упрощает контур, затем рёбра, близкие к горизонтали/вертикали, выравниваются. Итеративные проходы (3×) пропагируют snap на соседние рёбра.

## Решение

Smart snap: DP + H/V snap + collinear removal. Параметры относительные (% периметра / % размера), не абсолютные (px).

## Обоснование

1. **Относительные параметры.** `dp_eps_pct=0.15` (% периметра), `snap_threshold=0.08` (% длины ребра), `min_edge_pct=0.03` (% min(H,W)). Работают одинаково для символов 50px и 500px без перенастройки.
2. **Итеративный snap.** 3 прохода нужны, потому что snap одного ребра смещает вершину, что может сделать соседнее ребро snap-eligible.
3. **Collinear removal.** После snap появляются точки на одной прямой (threshold 1.5px cross-product) — удаление сокращает полигон без потери формы.
4. **Conservative defaults.** `snap_threshold=0.08` → snap если отклонение < 8% длины ребра. Не агрессивно, ошибки snap маловероятны.

## Последствия

- Параметры smart snap вынесены в `ContourExtractor.__init__()` и настраиваются через YAML-конфиг.
- Для нестандартных символов (диагональные рёбра) smart snap корректно не трогает рёбра с отклонением > 8%.
- Полигоны с < 3 вершин после snap → fallback на оригинальный DP полигон.
