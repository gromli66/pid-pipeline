Каждый документ указывает целевую аудиторию в шапке:

| Метка | Кто | Что знает |
|-------|-----|-----------|
| `DEV` | Разработчик (Python, PySide6) | Код, паттерны, как добавить фичу |
| `ML` | ML-инженер | Модели, обучение, данные, метрики |

## 4. Формат

### 4.1 Общее

- Markdown (.md)
- Максимум H1-H3 (без H4+)
- Оглавление если >3 секции
- Длина: столько сколько нужно, не больше. Без воды

### 4.2 Шапка каждого документа

```markdown
# [Название]

**Аудитория:** DEV / ML / OPS / ALL
**Версия:** X.Y
**Обновлено:** YYYY-MM-DD
**Связанные документы:** [ссылки]
```

### 4.3 Таблицы

Использовать для:
- Артефакт → путь → формат
- Параметр → тип → default → описание
- Endpoint → метод → путь → описание
- Статус → кто выставляет → следующий статус

### 4.4 Диаграммы

Mermaid для:
- Pipeline data flow
- Status machine transitions
- Наследование классов
- Docker compose topology

### 4.5 Код

- Блоки с указанием языка: ```python, ```yaml, ```bash, ```json
- Только реальный код из проекта или рабочие примеры
- Пути файлов — от корня проекта: `ui/editors/contour_editor.py`

### 4.6 JSON форматы

- Пример с комментариями (// не валиден в JSON — использовать отдельный блок с пояснениями)
- Обязательные поля пометить
- Типы: string, int, float, list, null

## 5. Правила описания

### 5.1 Pipeline и этапы

Каждый этап описывать по шаблону:

```markdown
### Этап N: [Название]

**Worker:** [имя] / **Queue:** [имя]
**Input артефакты:** [список с путями]
**Output артефакты:** [список с путями]
**Статус до:** [DiagramStatus]
**Статус после:** [DiagramStatus]
**Конфиг:** [секция в YAML]

[Описание логики]
```

### 5.2 Наследование классов

Показывать цепочку один раз, ссылаться:

```
BaseGraphEditor → SimpleGraphEditor → ContourEditor
BaseGraphTab → ContourTab
ModeHandler → ApplyContourHandler, EditPolygonHandler
Command → MoveVertexCommand, DrawPolygonCommand
```

### 5.3 Паттерны

Описывать паттерн один раз в CODING_GUIDE.md, в остальных документах ссылаться:
- Command (undo/redo) — см. CODING_GUIDE.md §3.1
- ModeHandler — см. CODING_GUIDE.md §3.2
- Overlay — см. CODING_GUIDE.md §3.3

### 5.4 Координаты и форматы данных

Всегда указывать формат:
- centroid: `[y, x]` (row, col)
- bbox: `[x1, y1, x2, y2]`
- polygon: flat `[x1, y1, x2, y2, ...]`
- source_point/target_point: `[y, x]`
- COCO bbox: `[x, y, w, h]`

### 5.5 Конфиг параметры

Каждый параметр:

```markdown
| Параметр | Тип | Default | Описание |
|----------|-----|---------|----------|
| `snap_dp_eps` | float | 0.15 | Douglas-Peucker epsilon как % периметра |
```

## 6. Протокол работы Claude

### При получении запроса:

1. **Прочитать** `DOCUMENTATION_RULES.md` (этот файл)
2. **Прочитать** все приложенные файлы кода
3. **Запросить недостающее** — назвать конкретные пути файлов (не больше 3 за раз)
4. **Показать оглавление** документа → дождаться утверждения
5. **Написать** документ секция за секцией
6. **В конце:**
   - Список новых терминов для GLOSSARY.md
   - Обновлённый статус в реестре документации (§8)

### Если файлов не хватает:

```
Для [название секции] мне нужны:
1. path/to/file1.py — [зачем]
2. path/to/file2.py — [зачем]
Приложи, пожалуйста.
```

### Если информация неизвестна:

Пометить `[TODO: уточнить ...]` — не выдумывать.
