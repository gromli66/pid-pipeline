# deploy_ready — комплект для миграции (Фаза 0)

Это **новые файлы-заготовки**, бэкап и код приложения не тронуты. Применяются на рабочей копии при миграции. Связаны с `../MIGRATION_PLAN.md` (дельты Д1–Д6, фазы 0–6).

## Что внутри

| Файл | Назначение | Куда |
|------|-----------|------|
| `.env.server.template` | Шаблон `.env` для сервера | скопировать в корень проекта на сервере как `.env`, заполнить |
| `docker-compose.override.yml` | Добавляет `CVAT_BROWSER_URL` в `api` (Д2), заметки по CSRF (Д4) и GPU (Д5) | положить рядом с `docker-compose.yml` на сервере |
| `01_change_ui_api_url.md` | Точечная правка UI — адрес API через `PID_API_URL` (Д1) | применить в коде рабочей копии (НЕ в бэкапе) |
| `run_ui_client.sh` / `.bat` | Запуск клиента с адресом сервера | на клиент (Astra / Windows) |
| `deploy_phase1.sh` | Развёртывание серверной части (Фаза 1/3, без воркеров) | на сервере |
| `offline_package.sh` | Скелет упаковки офлайн-комплекта (Фаза 5) | на онлайн-машине |

## Действия на твоей машине (я выполнить не могу — команды ниже)

### 1. Приватный git-репозиторий
```bash
# в корне проекта (рабочая копия, не бэкап)
git remote add origin <URL-приватного-репозитория>
git add -A && git commit -m "prep for migration"
git push -u origin main
```
> Репозиторий обязательно **приватный**. Модели, `.env`, архивы в git не попадут (они в `.gitignore`) — это правильно.

### 2. SSH-ключ для сервера
```bash
ssh-keygen -t ed25519 -C "pid-deploy"
# публичный ключ ~/.ssh/id_ed25519.pub добавить при создании ВМ
```

### 3. Дальше — по фазам из MIGRATION_PLAN.md
Фаза 1 (локально на Windows) → Фаза 2 (Astra-VM) → Фаза 3 (облачный сервер, `deploy_phase1.sh`).

## Порядок применения дельт
- Д1 — в коде клиента (`01_change_ui_api_url.md`).
- Д2/Д4 — через `.env` + `docker-compose.override.yml`.
- Д3 — токен CVAT генерируется уже на сервере (см. `deploy_phase1.sh`, шаг про суперпользователя).
- Д5 — для воркеров на CPU (Фаза 4): закомментировать GPU-блоки в `docker-compose.yml`, выставить `PID_DEVICE=cpu`.
- Д6 — на клиент положить папку `configs/`.
